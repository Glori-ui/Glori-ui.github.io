Data Analyst Job Market Analysis

  • Power BI

A dashboard that shows which tools, skills, qualifications and industries employers ask for in data analyst job postings.

The problem

People who want to become data analysts often don’t know what to learn first. I wanted to answer one question with data: what do employers actually ask for in data analyst job postings?

The data

Data analyst job postings. For each posting I looked at the tools, skills, qualifications and industry mentioned, then counted how often each one appeared.

My process

  1. Defined the questions: which tools, skills, qualifications and industries come up most?
  2. Organized the posting details into tools, skills, qualifications and industries.
  3. Counted how often each item was mentioned, and which tools were requested together.
  4. Built a Power BI dashboard so the answers can be read at a glance.

How I used the tools

  • Power BI: built the dashboard, with bar charts for tools and skills, a donut chart for qualifications, and a chart showing which tools are requested together.

Key findings

  • SQL is the most requested tool, mentioned about 105 times. Python (about 62) and Power BI (about 55) follow, then Tableau (about 41) and Excel (about 39).
  • Reporting is the most requested skill, at about 117 mentions, ahead of data visualization (about 62) and data cleaning / ETL (about 56).
  • SQL is usually paired with a BI tool. SQL with Power BI appeared about 41 times and SQL with Tableau about 37 times, compared with about 23 for SQL with Excel.
  • Degrees matter to many employers. A Master’s degree was mentioned 104 times and a Bachelor’s degree 66 times.
  • Most postings don’t name an industry (about 150), so the industry results are limited. Finance and healthcare were the most named.

The solution and recommendation

An aspiring analyst should learn SQL first, then one BI tool such as Power BI or Tableau, and practice building reports and dashboards from cleaned data. Communication and stakeholder skills also appear often, so presenting findings clearly is part of the job, not an extra.

What I learned

A clear question makes the whole analysis easier. I also learned that a result needs its limits stated: because most postings didn’t name an industry, I can’t say much about which industries hire the most.

Ghana Treasury Tender Analysis

  • Tableau Public

An interactive dashboard of Bank of Ghana Treasury tender data, showing how issuance and interest rates change by month and by type of security.

The problem

Treasury tender results are published as raw tables that are hard to read. I wanted to make them easy to explore: how do tenders change from month to month, which security types are issued, and how do interest rates move?

The data

Bank of Ghana Treasury tender data. Key fields include the tender ID, the security type, the issuance month and the interest rate.

My process

  1. Loaded the tender data into Tableau Public and checked that dates and security types were consistent.
  2. Built a monthly tender issuance view to show the trend over time.
  3. Counted tenders by security type to compare them.
  4. Added interest rate views: an overall analysis, a rate comparison, and the rate difference by month.
  5. Built a heatmap of tender activity, then combined the best views into one dashboard.

How I used the tools

  • Tableau Public: built each sheet (monthly tender issuance, security type analysis, interest rate analysis, rate comparison, rate difference by month and a tender activity heatmap), then arranged them into the final dashboard and published it online.

What the dashboard shows

  • How many tenders were issued each month.
  • Which security types make up the tenders.
  • How interest rates compare across securities and change from month to month.
  • When tender activity was busiest, shown as a heatmap.

The solution and recommendation

Putting issuance, security types and rates side by side lets someone following government borrowing see the full picture in one place, instead of reading separate tables. Anyone can filter and explore it themselves.

What I learned

I learned how to turn a raw public dataset into a dashboard that tells a story, and to choose the chart type that fits each question.
